# iTimer

> 给大脑的活动监视器 —— 一个会数你同时开了几个线程的计时器。

普通计时器默认你一次只做一件事。现实不是：写方案时回消息，回消息时看群，看群时想起还有个 bug。iTimer 不假装你是单线程的，它诚实地记录**同一时刻有几件事在计时**，并把这份碎片化程度变成看得见的数字。

「脑裂（split-brain）」本是分布式系统的术语：集群里的节点各自为政、互相打架。你的注意力也一样。

## 下载与安装

前往 [GitHub Releases](https://github.com/DueGin/iTimer/releases/latest) 下载 DMG，要求 macOS 14 或更新版本。在「关于本机」查看芯片类型：

| Mac 芯片 | 安装包文件名 |
|---|---|
| Apple Silicon（M 系列） | `iTimer-x.y.z-macos-arm64.dmg` |
| Intel | `iTimer-x.y.z-macos-x86_64.dmg` |

打开 DMG，将 iTimer 拖到 Applications。每个 Release 附带 `SHA256SUMS`，可用 `shasum -a 256` 校验下载的安装包。

当前安装包使用临时签名，尚未经过 Apple Developer ID 签名和公证。首次打开如被 macOS 拦截，请在「系统设置 › 隐私与安全性」中选择「仍要打开」。

## 定位

| | |
|---|---|
| **给谁** | 同时推进多条线的知识工作者：独立开发者、运营、创业者、PM |
| **解决什么** | 「今天好忙但好像什么都没做完」——忙的是切换，不是产出 |
| **不做什么** | 不做团队协作、不做计费工时、不做自动监控。一切由你手动开始、手动收尾，数据只在本机 |
| **一句话** | 记录时间，也记录注意力碎成了几瓣 |

## 核心概念

- **线程**：一个正在计时的任务。
- **脑裂线**：同时计时的任务数达到它就算脑裂（默认 3，可在 2–8 之间调）。
- **上下文切换**：已有任务在跑时又开一个新线程，记一次。
- **单核**：只有一个任务在计时的时间，也是连续天数（🔥）的依据：每天单核满 25 分钟 +1。
- **专注度（0–100）**：单核时间全额计入，并行计 55%，脑裂计 15%，再按每小时切换次数扣分（最多 15 分）。
  - 85+ 心流 · 65+ 稳定 · 40+ 分散 · 其余 过载
- **子任务**：一个任务下面可以挂一层子任务，用来拆步骤。点任务行上的「添加子任务」按钮（或右键 › 子任务 › 添加子任务…），父任务下方会出现输入框，回车添加一条，可以连续添加，Esc 结束；新子任务先放在「时间待定」，想做时点开始即可。也可以右键一个已有任务 › 子任务 › 归入其他任务。子任务不能再往下嵌套。父任务和它没完成的子任务在列表里是一组，子任务缩进排在父任务下面，整组跟着组里最靠前的那一项走，例如有一个子任务在计时，整组就排在「进行中」。父任务行显示完成进度（如 `1/3`），点进度胶囊（或右键 › 折叠子任务）可以把子任务收起来，折叠状态会记住，收起时如果有子任务在计时，胶囊旁会亮一个小圆点，添加子任务时会自动展开。删除父任务会一并删除它的子任务。
- **标签**：每个任务可以打多个自由标签，不需要预先创建。
- **备注与进展**：每个任务有一条常驻备注（结论、约束、下次接着做什么），以及按时间追加的进展评论。做着做着随手记一句，比事后回忆准。
- **工作流**：把要按顺序推进的事画在一张无限画布上。卡片就是普通任务（照常计时、进统计、写日历），连线表示「先做完这个，才轮到那个」。可以建多个工作流，一个任务同一时间只在一个工作流里；连线不能绕成环。上游全部完成的卡片亮成橙色「可开始」，还有上游没完成的显示「等待上游」，任务列表里也会标出「等上游」。每张卡片可以单独打开「上游完成后自动开始」（卡片上显示 ⚡），这样上一步一完成它就开始计时；没打开的只会亮起来等你开始，不替你多开线程。等待上游只是提示，想先开始也可以直接开始。
- **目标**：一件要花几周甚至几个月的大事，例如「iTimer 商业化」「做完个人网站」。每个目标有一张路线图，上面是一个个里程碑，连线表示「先达成这个，才轮到那个」，同样不能绕成环。目标可以写一段说明：为什么做、怎样算成功。
- **里程碑**：路线图上的每张卡片就是一个工作流，双击进去照常拆步骤、计时。一个工作流同一时间只在一个目标里。里程碑可以写完成标准、定目标日期（卡片上显示「还剩 N 天」或「已逾期 N 天」）；投入时长是它所有任务（含子任务）的计时总和。状态有五种：等待上游（上游里程碑还没达成，自己也还没开始）、可开始、推进中（有任务开始过）、待确认（任务都做完了）、已达成。任务做完不等于达成，要你点一下「标记达成」，因为里程碑看的是结果，比如「拿到 10 个付费用户」；达成之后，下游的里程碑才亮成「可开始」。

## 界面

**菜单栏**：一个会裂开的大脑图标。一个任务时显示计时，多个任务时显示 `12:34 ×2`，到脑裂线就变红并显示「脑裂 3」。

越过脑裂线的那一刻，图标会**炸开**：先鼓胀、发抖、蓄力，然后一道闪光，两半脑子飞开并翻转，碎片四散，最后弹回裂开的形状。线程开得越多，爆炸越猛。只要一直处于脑裂，每隔几秒会有一次小余震（发抖加火星）。面板打开时动画会停住，关上后再继续，所以在面板里开第三个任务，关上面板的瞬间它就会炸。系统开了「减弱动态效果」时不播放。

**弹出面板**
- 主卡片：最久的那个线程的大号计时；右上角是「线程槽」，一格一个线程，槽位数就是脑裂线，最后一格描了粉边，一眼看出还剩几个名额。
- 今日色带：从今天第一次计时到现在的负载条，青色专注、橙色并行、粉色脑裂。
- 每个任务一行：左侧圆钮暂停或继续，◎「只做这个」一键暂停其他所有线程，✓ 完成，添加子任务，双击标题改名，删除要连点两下。右键有完整菜单；菜单开着时计时数字会暂停，关掉后跳回正确的时间。
- 今日完成：做完的事不会消失，可以一键「再来一段」。
- 输入框的占位文字会随负载变化：「再开一个就到脑裂线了…」，开新线程前先提醒你一下。
- 最近做过的事以胶囊形式列出，点一下直接开始，输入时会自动过滤。
- 输入框支持 `写周报 #汇报 #PPT`：`#` 打标签。输入 `#` 时下方会出现已有标签的补全。
- 列表按状态分成「到点待开始 / 进行中 / 已暂停 / 接下来 / 时间待定 / 今日完成」，分区旁的数字是处于这个状态的任务数。
- 任务行显示 `#标签`；右键菜单里的「子任务」「标签」可以直接添加子任务或切换标签。
- 任务行的气泡按钮打开「备注和进展」：备注随时改，进展按时间追加，记过的任务会亮起气泡。
- 日程表单：日期一行直接列出「待定 / 今天 / 明天 / 后天 / 下周一」，其他日期点右侧日历按钮选；表单里还有标签一行，点选即可。

**主窗口**：布局和滴答清单类似。
- 最左边是常驻的图标栏：任务 ⌘1、目标 ⌘2、工作流 ⌘3、分析 ⌘4，底部是设置。图标上有角标：任务有在计时就亮小圆点，目标显示待确认的里程碑数，独立工作流里有步骤在计时也亮小圆点。
- 任务：图标栏右边是一列清单，有全部、到点待开始（有任务到点时才出现）、进行中、已暂停、接下来、时间待定、今日完成，下面按标签列出，每项后面是任务数。点一项，右边的日程列表就只显示这一类，内容和弹出面板一样。顶部的 + 新建任务（⌘N）。
- 目标、工作流：图标栏右边同样有一列列表。目标列表是各个目标和它下面的里程碑，工作流列表是不属于任何目标的工作流。顶部的 + 和底部按钮用来新建（目标 ⌥⌘N，工作流 ⇧⌘N），右边是路线图或工作流画布。
- 分析：没有列表，注意力分析占满右边。
- 工具栏左侧的按钮（⌃⌘S）收起或展开这列列表。收起后只剩图标栏，照样能切换模块。
- 切到别的模块再回来，目标和工作流会回到上次打开的那一个。
- 列表行：目标行显示已达成的里程碑数和待确认的数量，点左侧箭头可以收起里程碑；工作流行显示完成进度、可开始的步数，有步骤在计时时亮一个小圆点。右键可以改名、排序、删除：删除工作流时任务保留，只丢连线和布局；删除目标时里程碑和任务都保留，变回独立的工作流。独立的工作流右键可以「加入目标」。

**目标菜单**：顶部菜单栏的「目标」菜单列出所有目标，点一下直接打开它的路线图；「新建目标」（⌥⌘N）新建一个并等你命名。主窗口关着也能用。

**注意力分析**
- 专注度圆环、结论和五个关键数字（活跃、单核、脑裂占比、上下文切换、峰值线程），每项都和上一周期对比：今天对昨天同一时段，7 天对前 7 天，30 天对前 30 天。箭头颜色按「好坏」而不是「涨跌」来定，例如切换次数变多显示为粉色。悬停数字可以看到它的定义。
- 洞察卡片：用大白话说出值得注意的事，例如「15 点最容易脑裂」「每小时切换 4.0 次」「最长单核 1 小时 10 分」
- 今天：线程泳道（每个任务一条泳道，脑裂时段用粉色底色标出）和负载曲线
- 7 天、30 天、全部：专注度趋势（每天一个分数，没计时的日子会断开）和按天构成
- 时段分布、各级时长、标签环形图、常一起做的事、记录（超过 8 条时折叠）
- 所有图表都能悬停：泳道和负载曲线会显示时间游标，并列出那一刻有哪些任务在跑；柱状图会高亮悬停的那一根，其他变淡，同时弹出明细；悬停标签图例会高亮对应的扇区

**工作流画布**
- 平移：双指滑动，或拖动空白处；缩放：双指捏合、⌘ + 滚轮、左下角的 − / + 或 ⌘- / ⌘=，点百分比回到 100%，⌘0 适应窗口。第一次打开会自动缩放到能看全所有卡片，之后记住你上次停在哪里。
- 新建步骤：双击空白处，或点工具栏的「新步骤」（选中卡片时接在它后面）。输入框支持 `#标签`，回车添加后输入框自动挪到右边并接上连线，可以一口气打出一条链，Esc 结束。新步骤是「时间待定」的日程。
- 放入已有任务：从中间的列表把任务拖到画布上，或用工具栏的「添加已有任务」搜索后点选；任务行右键 › 工作流也能放进某个工作流，或「放进新工作流」。已在别的工作流里的任务会被移过来。
- 连线：从卡片右侧的圆点拖到另一张卡片上；拖到空白处松手，就地新建下一步。点圆点等于「添加下一步」。连线会被拒绝（提示音）的情况：重复、连到自己、绕成环。上游已完成的连线是实线，还没完成的是虚线。
- 卡片：左侧色条和下方的状态（等待上游 / 可开始 / 计时中 / 已暂停 / 已完成）同色，下方还有开始、暂停、完成按钮。拖动卡片移动位置（会吸附到半格），双击标题改名。右键菜单里有开始/暂停/完成、只做这个、上游完成后自动开始、添加下一步、改名、从工作流移除、删除任务。
- 选中卡片或连线后按 Delete：卡片只是从画布移除（任务还在），连线直接删掉；选中的连线中间也有一个 × 按钮。
- 「自动整理」按依赖深度把卡片排成几列。右下角是可开始、进行中、等待上游的数量和完成进度。

**目标路线图**
- 平移、缩放、连线、拖动卡片、自动整理和 Delete 都和工作流画布一样，只是卡片更大、排得更开。
- 新建里程碑：双击空白处，或点工具栏的「新里程碑」。回车后输入框挪到右边并接上连线，可以一口气排出一串，Esc 结束。每个新里程碑都是一个新的空工作流。「添加已有工作流」把现有的工作流放上来，已在别的目标里的会被移过来。
- 卡片：左侧色条和状态同色（橙色表示在等你：可开始或待确认），下面是任务进度、投入时长和目标日期。双击卡片打开它的工作流，双击标题改名；进了工作流后，窗口标题显示「目标 › 里程碑」，点左上角的「返回路线图」回来。卡片上的日历按钮打开「目标日期与完成标准」。右键菜单里有打开工作流、标记达成或撤销达成、添加下一个里程碑、改名、从目标移除。
- 上游已达成的连线是实线，还没达成的是虚线。按 Delete 只把卡片移出路线图，工作流还在。
- 工具栏的「目标说明」可以改名，写下为什么做、怎样算成功，内容显示在左上角。右下角是可开始、推进中、待确认、等待上游的数量和达成进度。

**交互**：所有自定义按钮共用一套 hover 反馈：悬停时浮出带色背景，部分按钮会轻微放大，图标变成对应颜色，按下时会压缩一下。任务行、记录行、「常一起做的事」的每一行悬停时背景会变亮。最近任务的胶囊按钮悬停时会显示 ▶。

**提醒**：进入脑裂时发通知，建议用「只做这个」收拢线程；单个任务连续计时 3 小时会提醒你是不是忘了暂停；工作流里完成一步时，告诉你哪些下一步已经自动开始、哪些可以开始了。这几种提醒都能在设置里关掉。

**设置（⌘,）**：脑裂线、提醒开关、日历同步、登录时启动、打开数据文件所在位置。

## 设计原则

1. **诚实而不说教**：文案带点自嘲（「左右脑互搏」「脑子裂成 3 瓣」），只陈述发生了什么，不评判你。
2. **颜色即语义**：青色、橙色、粉色只表示专注、并行、脑裂；标签配色刻意避开这三种颜色。
3. **在开新线程前介入**：线程槽、输入框提示、脑裂通知，都在你「再开一个」之前轻轻拦一下。
4. **一键收拢**：发现脑裂后，恢复只需要一下点击（◎ 只做这个）。

## 构建

```bash
./scripts/build-app.sh release   # 输出 dist/iTimer.app
./scripts/build-dmg.sh           # 打包本机架构的 DMG
swift test                       # 核心逻辑测试
```

指定架构构建和打包：`./scripts/build-app.sh release arm64` 后运行 `./scripts/build-dmg.sh arm64`；Intel 版把 `arm64` 换成 `x86_64`。

数据保存在 `~/Library/Application Support/iTimer/state.json`。

## 自动发版

流水线会在 `main` 推送和 Pull Request 时，检查 Apple Silicon 和 Intel 两个架构的核心测试、应用构建和 DMG 打包。发版前先确认这些检查通过。

按 [发版约定](AGENTS.md#发版) 更新应用版本号、build 号和版本文档，提交后推送 `vx.y.z` 格式的 tag：

```bash
git tag v1.8.3                   # 示例：应用版本号须已更新为 1.8.3
git push origin v1.8.3
```

[发版流水线](.github/workflows/release.yml) 会检查 tag 与应用版本号是否一致，以及 CHANGELOG 是否有对应版本的更新内容；在 Apple Silicon 和 Intel runner 上分别运行核心测试、构建应用并打包。两边都成功后，自动创建 GitHub Release，上传两个 DMG 和 `SHA256SUMS`，更新说明取自该版本的 CHANGELOG。

流水线使用 GitHub 自带的 `GITHUB_TOKEN`，发布 job 有 `contents: write` 权限，无需配置额外 Secret。上传附件时先创建草稿，全部上传成功再公开；失败后可在 Actions 中重新运行，继续上传草稿中的附件。已公开的 Release 不会被覆盖。

如果 tag 推送后没有出现运行记录，可在 Actions ›「构建与发布 iTimer」› Run workflow 中选择 `main`，填入已有的版本 tag（如 `v1.8.2`）。手动运行会检出该 tag 的代码，并执行相同的版本检查、双架构构建和发布流程。
